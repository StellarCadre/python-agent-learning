# 02_tuple.py 疑惑详解：tuple 的"不可变"到底指什么

> 本文档针对 `02_tuple.py` 第 66 行的表述：
> **"tuple 不可变指的是'引用'不可变，引用指向的对象内部可变"**
> 进行深入讲解。

---

## 一、前提：tuple 里存的是引用，不是对象本身

和 list 一样，tuple 的每个位置存的是**对象的地址（引用）**，不是把对象整个塞进去。

```python
nested_t = (1, 2, [3, 4])
```

内存示意：

```
tuple ──→ [ ref1 , ref2 , ref3 ]
             │       │       │
             ▼       ▼       ▼
            1       2     [3, 4]     ← 一个独立的 list 对象
```

tuple 的三个格子里，分别写着三个对象的地址。

---

## 二、"不可变"锁的是格子里的地址，不是地址里的东西

tuple 保证的是：**每个格子里写的地址永远不能换**。

### 会报错的操作（换了地址）

```python
nested_t[0] = 999      # TypeError：要把 ref1 从"指向1"改成"指向999"，换了地址
del nested_t[0]        # TypeError：要删掉一个格子
```

### 可以的操作（地址没变，改的是对象内部）

```python
nested_t[2].append(5)  # OK：ref3 还是指向原来那个 list，地址没换
                       #     只是 list 自己内部多了个元素
```

执行后内存：

```
tuple ──→ [ ref1 , ref2 , ref3 ]     ← 三个地址完全没变！
             │       │       │
             ▼       ▼       ▼
            1       2     [3, 4, 5]  ← list 内部变了
```

**tuple 从头到尾没动过，变的是它引用的那个 list。**

---

## 三、类比理解

把 tuple 想象成一本**写死了地址的通讯录**：

- 通讯录上写着：张三住 101 室，李四住 102 室
- **你不能把通讯录上的地址涂改**（tuple 不可变）
- 但 **101 室的人可以重新装修房子**（list 内部可变）
- 装修完了，通讯录上的地址还是 101，没变

---

## 四、为什么 int 就"看起来"完全不可变？

```python
t = (1, 2, 3)
```

这里三个元素都是 int，而 int 本身是**不可变对象**——你根本没法修改 `1` 这个对象的内部（它没有内部可改）。所以当元素全是不可变类型时，tuple 表现得"彻底不可变"。

但一旦元素里混进了 list/dict/set 这些可变对象，就出现了"tuple 不可变，但里面的东西在变"的现象。

| tuple 元素类型 | 能否修改元素内部 | 整体表现 |
|---|---|---|
| int / str / tuple（不可变） | 不能 | 彻底不可变 |
| list / dict / set（可变） | 能 | 引用不可变，内容可变 |

---

## 五、一个直接后果：含可变对象的 tuple 不能做 dict 的 key

```python
good = (1, 2, 3)
d = {good: "可以"}          # OK，全不可变，可哈希

bad = (1, [2, 3])
# d = {bad: "不行"}         # TypeError: unhashable type: 'list'
```

因为 dict 的 key 要求哈希值稳定。如果 tuple 里有 list，list 一变，tuple 的"逻辑内容"就变了，哈希值就不稳定了——所以 Python 直接禁止它哈希。

---

## 六、Go 对比

这和 Go 里的情况几乎一样：

```go
// Go：数组里存指针，数组本身固定，但指针指向的内容可变
var arr [3]*[]int
s := []int{3, 4}
arr[2] = &s
(*arr[2]) = append(*arr[2], 5)   // 可以，arr[2] 这个指针没换，指向的 slice 变了
```

更贴切的类比：Go 的 `struct` 里有个指针字段，struct 本身如果是只读的（概念上），字段指针不能改指向，但指针指向的堆上数据可以改。

---

## 七、总结

1. tuple 存的是对象的引用（地址），不是对象本身
2. **不可变 = 每个格子的地址不能换**，不能增删改元素的指向
3. **地址指向的对象如果是可变的（list/dict/set），其内部可以改**
4. 元素全是不可变类型时，tuple 表现为彻底不可变
5. 含可变对象的 tuple 不可哈希，不能做 dict 的 key

> **一句话：tuple 锁的是"我存的地址"，不锁"地址里那栋房子的内部装修"。**
