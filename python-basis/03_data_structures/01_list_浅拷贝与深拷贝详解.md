# 01_list.py 疑惑详解：浅拷贝与深拷贝

> 本文档针对 `01_list.py` 中第 68 行（切片浅拷贝）、第 190 行（三种复制方式）、第 197 行（浅拷贝坑与深拷贝）三处内容进行深入讲解。

---

## 一、前提 1：Python 变量是"标签"，不是"盒子"

这是理解一切的基础。

Go 的变量是一个**装值的盒子**，赋值时把值复制进盒子。
Python 的变量是**贴在对象上的名字标签**，赋值只是多贴一个标签，不复制对象。

```python
a = [1, 2, 3]
b = a          # 不是复制！只是给同一个对象多贴了一个标签
```

内存示意：

```
a ──┐
    ├──→ [1, 2, 3]   （同一个列表对象）
b ──┘
```

所以 `b[0] = 999` 会同时影响 `a`，因为根本就是同一个东西。这叫**引用共享**，连拷贝都算不上。

> **Go 对比**：Go 里 `b := a`，如果 a 是数组（值类型）会真复制；如果是 slice/map（引用类型）则共享底层数据。Python 的 list 行为更接近 Go 的 slice，但 Python 所有赋值都是贴标签。

---

## 二、前提 2：list 里存的是引用，不是对象本身

这是第二个关键前提。`[[1, 2], [3, 4]]` 在内存里不是嵌套的实体，而是：

```
外层列表 ──→ [ ref1 , ref2 ]
               │      │
               ▼      ▼
            [1,2]  [3,4]     （两个独立的子列表对象）
```

外层列表存的是**子列表的地址（引用）**，不是把子列表整个塞进去。

---

## 三、三种操作的本质区别

### 1. 赋值 `b = a`：完全共享，零拷贝

```
a ──┐
    ├──→ 外层列表 [ref1, ref2]
b ──┘
```

改 `b` 的任何东西，`a` 都变。

### 2. 浅拷贝 `b = a.copy()` / `a[:]` / `list(a)`：只复制最外层

```
a ──→ 外层列表A [ref1, ref2]
              │      │
              ▼      ▼
           [1,2]  [3,4]      ← 子列表共享！
              ▲      ▲
              │      │
b ──→ 外层列表B [ref1, ref2]   ← 外层是新的，里面的引用还是旧的
```

**浅拷贝只复制了"外层容器"，容器里装的引用原封不动复制过去。** 外层是两个独立对象，但里面指向的子列表还是同一个。

### 3. 深拷贝 `b = copy.deepcopy(a)`：递归复制所有层级

```
a ──→ 外层列表A [ref1, ref2]
              │      │
              ▼      ▼
           [1,2]  [3,4]

b ──→ 外层列表B [ref3, ref4]
              │      │
              ▼      ▼
           [1,2]  [3,4]      ← 子列表也是全新的！
```

**深拷贝递归地把每一层都复制一份**，完全独立，互不影响。

## 四、为什么文件里说"切片是浅拷贝，修改切片不影响原列表"？

对应 `01_list.py` 第 68-71 行：

```python
nums2 = [0, 1, 2, 3, ...]
copy_nums = nums2[:]        # 浅拷贝
copy_nums[0] = 999
print(nums2[0])             # 0，原列表不变
```

这里不影响，是因为 `nums2` 是**一维列表，元素是 int（不可变对象）**。

浅拷贝后，`copy_nums[0] = 999` 做的事是：**让 copy_nums 的第 0 个位置指向新的 int 对象 999**，而不是修改原来的 int 对象。int 不可变，只能换引用，所以原列表不受影响。

```
浅拷贝后：
nums2[0]     ──→ 0（int 对象，不可变）
copy_nums[0] ──→ 0（同一个 0）

执行 copy_nums[0] = 999 后：
nums2[0]     ──→ 0（没变）
copy_nums[0] ──→ 999（指向了新对象）
```

## 五、为什么嵌套列表浅拷贝就"翻车"了？

对应 `01_list.py` 第 197-201 行：

```python
nested1 = [[1, 2], [3, 4]]
shallow = nested1.copy()
shallow[0][0] = 999
print(nested1)    # [[999, 2], [3, 4]]  原列表也变了！
```

因为 `shallow[0]` 和 `nested1[0]` 指向**同一个子列表对象**。`shallow[0][0] = 999` 是**修改这个子列表对象的内部**（list 是可变的），不是换引用。两个外层列表都看着它，所以都变了。

```
nested1[0] ──┐
             ├──→ [1, 2]  ← 同一个子列表，被改成 [999, 2]
shallow[0] ──┘
```

### 一句话区分

| 操作 | 含义 | 浅拷贝是否影响原列表 |
|---|---|---|
| `b[0] = 新东西` | 改外层元素的引用（换指向） | 不影响 |
| `b[0][0] = 新东西` | 改内层可变对象的内部 | 影响 |

---

## 六、不可变 vs 可变，决定了浅拷贝是否安全

| 元素类型 | 浅拷贝后修改内层 | 是否影响原列表 |
|---|---|---|
| int / float / str / tuple（不可变） | 只能换引用，不能改内部 | 不影响 |
| list / dict / set（可变） | 可以改内部 | 影响 |

所以：
- **一维列表，元素全是不可变的** → 浅拷贝完全够用，和深拷贝效果一样
- **嵌套了 list/dict/set** → 浅拷贝有坑，需要深拷贝

---

## 七、深拷贝的代价

`copy.deepcopy()` 要递归遍历整个结构，**性能差、可能很慢**。而且它会尝试复制一切，包括你不想复制的东西（比如文件句柄、网络连接——这些深拷贝可能报错或无意义）。

**原则：能浅拷贝就浅拷贝，只有嵌套可变对象且需要完全独立时才用深拷贝。**

---

## 八、Go 对比

| 操作 | Go | Python |
|---|---|---|
| 赋值共享 | slice/map 共享底层 | 所有对象共享引用 |
| 浅拷贝 | `copy(dst, src)` 复制元素（元素是指针则共享指针） | `.copy()` / `[:]` / `list()` |
| 深拷贝 | 无内置，自己写递归或用第三方库 | `copy.deepcopy()` |

Go 的 `copy()` 复制 slice 元素，如果元素是指针或 struct 里有指针，底层数据仍然共享——本质和 Python 浅拷贝一样。

---

## 九、总结

1. Python 变量是标签，赋值不复制
2. list 存的是引用，不是对象本身
3. **浅拷贝**：只复制最外层容器，内层引用共享
4. **深拷贝**：递归复制所有层级，完全独立
5. 一维不可变元素列表，浅拷贝安全；嵌套可变对象，浅拷贝有坑
6. 深拷贝性能差，按需使用
