# Python 四大容器：list / tuple / dict / set 特性全解与选型指南

> 本文档不罗列具体方法（append/pop/get 等），聚焦**核心特性、本质区别、性能特征与选型决策**。
> 面向有 Go 基础的开发者，全程对比 Go 对应概念。

---

## 一、总览：四种容器的定位

| 容器 | 一句话定位 | Go 对应物 |
|---|---|---|
| **list** | 有序、可变的序列，什么都能装 | slice |
| **tuple** | 有序、不可变的序列，轻量且安全 | 固定长度数组 / 多返回值 |
| **dict** | 键值对映射，按 key 快速查找 | map |
| **set** | 无序、不重复的集合，用于去重和集合运算 | map[T]struct{} |

四者覆盖了程序中 95% 以上的数据组织需求。理解它们的**特性边界**，比记住方法名重要得多。

---

## 二、list（列表）

### 核心特性

| 维度 | 特性 |
|---|---|
| **有序性** | 有序，按插入顺序排列，支持索引（含负索引）和切片 |
| **可变性** | 可变：可增、删、改元素，长度可动态变化 |
| **元素类型** | 任意类型，可混合（int、str、list、dict 都能放） |
| **重复** | 允许重复元素 |
| **可哈希** | 不可哈希，不能做 dict 的 key |
| **底层实现** | 动态数组（over-allocate，预留空间），类似 Go slice 的 cap 机制 |

### 深入理解

- **有序 = 有索引**：list 是唯一同时支持"正索引、负索引、切片、步长"的容器。`lst[-1]`、`lst[::-1]` 这些操作是 list/tuple 专属。
- **可变 = 原地修改**：`lst[0] = x`、`lst.append()` 直接改原对象，不创建新 list。这意味着函数传 list 进去，函数内修改会影响外部（Go 传 slice 同理，共享底层数组）。
- **混合类型**：`[1, "a", True, [2, 3]]` 合法，但实际开发中**强烈建议保持元素类型一致**，否则遍历时要不断判断类型，可读性差。
- **动态扩容**：append 时如果容量不够，会申请更大的内存并复制，均摊复杂度 O(1)。和 Go slice 的 append 扩容机制本质相同。

### 性能特征

| 操作 | 时间复杂度 |
|---|---|
| 按索引访问 `lst[i]` | O(1) |
| 末尾 append/pop | O(1) 均摊 |
| 头部 insert(0)/pop(0) | O(n)（元素整体后移/前移） |
| 按值查找 `x in lst` | O(n) |
| 按值删除 remove | O(n) |
| 切片 `lst[a:b]` | O(k)，k 为切片长度（浅拷贝） |

### 典型用途

- 有序数据集合（用户列表、消息队列、日志序列）
- 需要动态增删的序列
- 栈（append + pop 模拟）
- 函数返回多个同类型结果

## 三、tuple（元组）

### 核心特性

| 维度 | 特性 |
|---|---|
| **有序性** | 有序，支持索引和切片（和 list 完全一致） |
| **可变性** | **不可变**：创建后不能增、删、改元素的指向 |
| **元素类型** | 任意类型，可混合 |
| **重复** | 允许重复元素 |
| **可哈希** | 元素全不可变时可哈希，能做 dict 的 key；含可变对象则不可哈希 |
| **底层实现** | 固定长度数组，无预留空间，比 list 更省内存 |

### 深入理解

- **不可变的精确含义**：tuple 锁的是"每个位置存的引用（地址）"，不是引用指向的对象内部。
  - `t[0] = x` → 报错（换了引用）
  - `t[2].append(5)`（t[2] 是 list）→ 合法（没换引用，改的是 list 内部）
  - 详见 `02_tuple_不可变原理详解.md`
- **不可变带来的好处**：
  1. **安全**：作为函数参数传递，不用担心被意外修改
  2. **可哈希**：能做 dict 的 key、能放进 set（list 不行）
  3. **性能**：创建比 list 快，占用内存更小
  4. **语义清晰**：告诉阅读者"这个数据结构不应该被修改"
- **单元素 tuple 的坑**：`(42)` 是 int，`(42,)` 才是 tuple。逗号才是 tuple 的标志，括号不是。
- **函数多返回值本质是 tuple**：`return 1, "Tom"` 返回的是 `(1, "Tom")`，接收时解包。
- **解包（unpacking）是 tuple 的核心场景**：`a, b = (1, 2)`、`a, *rest = (1,2,3,4)`，这是 Go 没有的灵活语法。

### 性能特征

| 操作 | 时间复杂度 |
|---|---|
| 按索引访问 | O(1) |
| 拼接 `t1 + t2` | O(n+m)（创建新 tuple） |
| 重复 `t * 3` | O(n) |
| `x in t` | O(n) |

> tuple 没有 append/remove/sort 等修改方法，因为不可变。需要"修改"时只能创建新 tuple。

### 典型用途

- 函数返回多个值（最常见）
- 固定结构的数据记录（如坐标 `(x, y)`、RGB 颜色 `(r, g, b)`）
- 作为 dict 的复合 key（如经纬度 `(lat, lng)`）
- 保护不应该被修改的数据
- 解包赋值、交换变量 `a, b = b, a`

## 四、dict（字典）

### 核心特性

| 维度 | 特性 |
|---|---|
| **有序性** | Python 3.7+ **保持插入顺序**（Go map 无序） |
| **可变性** | 可变：可增、删、改键值对 |
| **key 类型** | 必须可哈希（不可变：str/int/tuple/frozenset）；list/dict/set 不能做 key |
| **value 类型** | 任意类型，可混合 |
| **重复** | key 不允许重复（后赋值覆盖前值）；value 可重复 |
| **可哈希** | 不可哈希 |
| **底层实现** | 哈希表（hash table），Python 3.6+ 用紧凑哈希表，兼顾顺序和性能 |

### 深入理解

- **key 必须可哈希**：哈希表通过 key 的哈希值定位存储位置。如果 key 可变（如 list），哈希值会变，就找不到了。所以 dict 的 key 必须是不可变类型。
  - `{(1,2): "坐标"}` ✅
  - `{[1,2]: "坐标"}` ❌ TypeError
- **查找是 O(1)**：这是 dict 最大的价值。通过 key 直接算位置，不用遍历。`d["key"]` 无论 dict 多大都是常数时间。
- **插入顺序**：Python 3.7 之前 dict 无序，3.7 之后保证插入顺序。这是 Python dict 和 Go map 最大的行为差异之一。
- **get() 的重要性**：`d["missing"]` 会抛 KeyError，`d.get("missing")` 返回 None，`d.get("missing", 默认值)` 更安全。Agent 开发中处理 JSON/模型输出时 get 极其高频。
- **bool 是 int 的子类**：`True` 和 `1` 是同一个 key，`False` 和 `0` 是同一个 key。`{True: "a", 1: "b"}` 结果是 `{True: "b"}`。
- **dict 和 JSON 天然对应**：JSON 对象 ↔ dict，JSON 数组 ↔ list，这是 Agent 调用大模型 API 时最核心的数据结构。

### 性能特征

| 操作 | 时间复杂度 |
|---|---|
| 按 key 取值 `d[k]` / `d.get(k)` | O(1) 平均 |
| 插入/修改 `d[k] = v` | O(1) 平均 |
| 删除 `del d[k]` / `d.pop(k)` | O(1) 平均 |
| 遍历 keys/values/items | O(n) |
| `k in d` | O(1) 平均（判断的是 key，不是 value！） |

> 哈希冲突时最坏退化到 O(n)，但实际几乎不会发生。

### 典型用途

- 键值对映射（配置、用户信息、API 响应）
- 快速查找/去重（用 key 做索引）
- 计数（词频统计：`{word: count}`）
- 分组（按类别聚合数据）
- JSON 数据的内存表示
- 模拟 switch/case（函数分发表 `{"add": add_func, "del": del_func}`）

## 五、set（集合）

### 核心特性

| 维度 | 特性 |
|---|---|
| **有序性** | **无序**（不保证顺序，遍历顺序可能变化） |
| **可变性** | 可变（普通 set）；frozenset 不可变 |
| **元素类型** | 必须可哈希（不可变类型）；list/dict/set 不能放入 set |
| **重复** | **不允许重复**（自动去重） |
| **可哈希** | 普通 set 不可哈希；frozenset 可哈希 |
| **底层实现** | 哈希表（和 dict 同源，只存 key 不存 value） |

### 深入理解

- **去重是核心价值**：`set([1,1,2,2,3])` → `{1,2,3}`。这是 Python 中最简单的去重方式，但**会丢失顺序**（Python 3.7+ dict 有序但 set 仍然无序）。
- **空 set 只能用 `set()`**：`{}` 创建的是空 dict，不是空 set。这是初学者高频坑。
- **成员判断 O(1)**：`x in set` 是哈希查找，比 `x in list`（O(n) 遍历）快得多。大数据量去重/判断存在性时，set 是首选。
- **集合运算是 set 的独门武器**：交集 `&`、并集 `|`、差集 `-`、对称差 `^`。这些运算 list/tuple 都没有，需要自己写循环。
- **无序的含义**：set 不保证插入顺序，也不保证排序。`{3,1,2}` 打印出来可能是 `{1,2,3}`，但这是哈希表的偶然表现，**不要依赖 set 的顺序**。
- **frozenset**：不可变版本的 set，可以做 dict 的 key，也可以嵌套进另一个 set。

### 性能特征

| 操作 | 时间复杂度 |
|---|---|
| `x in s` | O(1) 平均 |
| add / remove / discard | O(1) 平均 |
| 交集 `&` / 并集 `\|` / 差集 `-` | O(min(len(a), len(b))) |
| 遍历 | O(n) |

### 典型用途

- 列表去重（`list(set(lst))`，注意顺序丢失）
- 快速成员判断（黑名单、标签集合）
- 集合运算（找共同好友、差集对比、交集筛选）
- 去除重复同时不关心顺序
- 保持顺序的去重用 `dict.fromkeys(lst)`（Python 3.7+）

## 六、横向对比总表

### 6.1 核心特性对比

| 特性 | list | tuple | dict | set |
|---|---|---|---|---|
| **有序** | ✅ | ✅ | ✅ (3.7+) | ❌ |
| **可变** | ✅ | ❌ | ✅ | ✅ |
| **可索引** | ✅ | ✅ | 通过 key | ❌ |
| **可切片** | ✅ | ✅ | ❌ | ❌ |
| **允许重复** | ✅ | ✅ | key❌ value✅ | ❌ |
| **元素可混合类型** | ✅ | ✅ | value✅ key❌ | ❌（必须可哈希） |
| **可做 dict key** | ❌ | ✅* | ❌ | ❌（frozenset✅） |
| **可哈希** | ❌ | ✅* | ❌ | ❌ |
| **成员判断 in** | O(n) | O(n) | O(1) | O(1) |
| **创建语法** | `[]` / `list()` | `()` / `tuple()` | `{k:v}` / `dict()` | `set()`（`{}`是dict） |

> *tuple 可哈希的前提是其所有元素都可哈希。

### 6.2 可变性与哈希的关系

这是理解四种容器的关键线索：

```
不可变 → 可哈希 → 能做 dict 的 key / 能放进 set
可变   → 不可哈希 → 不能做 key / 不能放进 set
```

- **不可变**：int、str、float、bool、tuple（元素全不可变时）、frozenset、bytes
- **可变**：list、dict、set、bytearray

> 为什么可变对象不能哈希？因为哈希值依赖对象内容，对象一变哈希值就变，放在 dict/set 里就再也找不到了。

### 6.3 性能对比（大数量级下的体感差异）

| 场景 | list | tuple | dict | set |
|---|---|---|---|---|
| 10万元素判断 `x in` | ~10ms | ~10ms | <0.01ms | <0.01ms |
| 头部插入 | O(n) 慢 | 不支持 | O(1) | O(1) |
| 去重 | 需手写 O(n²) | 不支持 | O(n) | O(n) |
| 按序存储 | ✅ 首选 | ✅ 只读首选 | 按插入序 | ❌ |
| 内存占用 | 中 | 最小 | 较大 | 较大 |

## 七、选型决策：什么时候用什么

### 7.1 决策树

```
需要按 key 快速查找？
├── 是 → dict
└── 否
    ├── 需要去重 / 集合运算？
    │   ├── 是 → set
    │   └── 否
    │       ├── 数据创建后不会修改？
    │       │   ├── 是 → tuple（更安全、更省内存）
    │       │   └── 否 → list
    │       └── 需要有序 + 动态增删？
    │           └── list
```

### 7.2 场景速查表

| 场景 | 推荐 | 原因 |
|---|---|---|
| 用户列表、消息记录 | list | 有序、动态增删 |
| 函数返回 (code, msg, data) | tuple | 多返回值、不可变安全 |
| 配置项 key-value | dict | 按名查找 |
| API JSON 响应 | dict + list | JSON 天然对应 |
| 标签集合、去重 | set | 自动去重、O(1) 判断 |
| 坐标 (x, y)、RGB 颜色 | tuple | 固定结构、可哈希做 key |
| 词频统计 | dict | `{word: count}` |
| 找两个列表的共同元素 | set | 交集运算一行搞定 |
| 函数参数保护（不被修改） | tuple | 不可变 |
| 有序且需要去重 | dict.fromkeys | 3.7+ dict 有序 |
| 复合 key（经纬度查城市） | dict，key 用 tuple | tuple 可哈希 |
| 栈 / 队列 | list | append + pop |

### 7.3 常见组合技巧

这些是四种容器配合使用的"意想不到的功能"：

| 需求 | 写法 | 原理 |
|---|---|---|
| 列表去重（不保留顺序） | `list(set(lst))` | set 去重，再转回 list |
| 列表去重（保留顺序，3.7+） | `list(dict.fromkeys(lst))` | dict 有序且 key 唯一 |
| 找两个列表交集 | `list(set(a) & set(b))` | set 交集运算 |
| 找两个列表差集 | `list(set(a) - set(b))` | set 差集 |
| 列表元素计数 | `dict(Counter(lst))` 或手写 | dict 计数 |
| 按 key 分组 | `defaultdict(list)` | dict + list |
| 交换变量 | `a, b = b, a` | tuple 解包 |
| 函数多返回值 | `return x, y` | 本质返回 tuple |
| 函数分发表（替代 switch） | `{"add": add, "del": delete}` | dict 存函数引用 |
| 去重同时统计次数 | `Counter(lst)` | dict 子类 |
| 嵌套数据安全传递 | 外层 tuple 包 list | tuple 不可变保护引用，list 内部可改 |

## 八、与 Go 的核心差异总结

| 维度 | Go | Python |
|---|---|---|
| 有序 map | map 无序 | dict 3.7+ 有序 |
| 多返回值 | 原生支持 `(int, error)` | 本质是 tuple，语法更轻 |
| 集合类型 | 无内置，用 `map[T]struct{}` | 原生 set，支持运算符 |
| 不可变序列 | 数组 `[N]T`（值拷贝） | tuple（引用，但不可换指向） |
| 切片 | slice（共享底层数组） | list（动态数组，引用语义） |
| 类型混合 | 不允许（强类型） | 允许（动态类型，但不推荐） |
| 可哈希/做 key | 可比较类型可做 map key | 可哈希类型可做 dict key |

---

## 九、一句话总结

- **list**：需要有序、动态变化的序列 → 用它
- **tuple**：数据固定、不该被改、需要做 key → 用它
- **dict**：需要按名字/键快速查找 → 用它
- **set**：需要去重、判断存在、集合运算 → 用它

> 选型的核心不是"哪个功能多"，而是**匹配数据的语义**：有序还是无序、可变还是不可变、是否允许重复、是否需要按键查找。选对了容器，代码会自然简洁、性能也会好。
